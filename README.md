# be docs (안드로이드 문서 뷰어)

카카오톡 등에서 받은 **한글(hwp·hwpx), 워드(docx·doc), 엑셀(xlsx·xls·csv), 파워포인트(pptx·ppt), PDF, CAD 도면(dwg·dxf), 일러스트(ai)**를 열어 **보기만** 하는 앱.
RTF·ODT·ODP·웹 페이지로 저장된 .doc 같은 드문 형식은 **간단 보기**(글자·표·그림)로 연다.
광고·로그인·편집 기능이 없고, **인터넷 권한이 없어** 문서가 밖으로 나가지 않는다.

## 설치 (갤럭시)

1. GitHub에서 이 저장소의 **Actions → android** 최근 실행을 연다.
2. 아래쪽 **Artifacts**의 `be-docs-apk`를 받는다(zip).
3. 휴대폰 **내 파일**에서 zip을 풀고 `be-docs-xxxxxxx.apk`를 누른다.
4. 처음 한 번 "출처를 알 수 없는 앱 설치"를 허용한다.

새 버전도 같은 방법으로 설치하면 덮어쓰기된다(서명 키가 같아서 지우지 않아도 된다).
단, 배포 키(`store/release-checklist.md` 4번)를 처음 등록한 뒤의 APK는 그 전 APK(디버그 키 서명)와 서명이 달라 **한 번만** 지우고 다시 설치한다.
0.2.62부터 패키지 이름이 `com.squeecho.docviewer`로 바뀌어(플레이 등록 전, squeecho.com 도메인에 맞춤) 전의 be docs
(`io.github.squeecho.docviewer`)와는 **다른 앱**으로 깔린다. 새 앱을 깐 뒤 옛 be docs는 직접 지운다(두 개가 "연결 앱" 목록에 함께 보인다).

## 팀원에게 배포

- 가장 간단한 방법: 위에서 받은 `be-docs-xxxxxxx.apk`를 팀 카톡방에 파일로 올린다. 팀원은 카톡에서 받아 설치한다
  (GitHub 계정이 없어도 된다). 처음 한 번 "출처를 알 수 없는 앱 설치" 허용이 필요하다.
- **Play 프로텍트가 "기기 보호를 위해 앱 차단됨"(이 개발자의 앱을 검사한 적이 없음)으로 막을 때**: 먼저 "세부정보 더보기"에
  "그래도 설치"가 있는지 본다. 없으면 Play 스토어 > 프로필 > Play 프로텍트 > 설정(톱니)에서 "Play 프로텍트로 앱 검사"를 잠깐 끄고
  설치한 뒤 **바로 다시 켠다**. 이 앱은 권한을 하나도 요청하지 않지만, 처음 보는 개발자의 앱이라 막힌다.
  팀원마다 이 과정을 거치게 하지 않으려면 플레이 내부 테스트로 배포한다(`store/release-checklist.md`).
- 버전은 CI 실행 번호로 자동으로 올라가고(`0.2.<번호> (<커밋>)`), 앱 첫 화면 아래에 표시된다. 새 APK는 덮어 설치하면 된다.

  그 전에 [Android Developer Console](https://developer.android.com/developer-verification)의 무료 제한 배포 계정
  (기기 20대까지)에 아래 정보로 앱을 등록해 두면 된다.
  - 패키지 이름: `com.squeecho.docviewer`
  - 서명 인증서 SHA-256: `29:EA:82:1F:28:E7:D9:57:26:FD:67:59:92:E4:DF:7F:96:11:BF:20:09:3A:18:9D:F6:25:9B:C2:71:A0:18:EB`

## 사용

- **카톡**: 파일을 받은 뒤 열 때 나오는 앱 목록에서 **be docs**를 고른다.
  목록에 없으면 파일을 길게 눌러 **공유 → be docs**를 쓴다.
- **앱 아이콘**: 눌러서 **파일 열기**로 휴대폰에 있는 문서를 고른다. 전에 연 문서가 있으면 앱을 켜자마자 **최근 문서** 목록(최근 연 순서)이 나오고,
  누르면 바로 다시 열린다. 파일 고르기로 연 문서는 원본을(읽기 권한을 계속 받아 둠), 카톡·메일 등에서 받은 문서는 앱 안에 둔 사본을 연다
  (그 앱이 준 권한은 화면을 닫으면 끝나서. 열 때 받아 둔 캐시 사본에 하드 링크를 걸어 즉시·자리 더 안 쓰고, 같은 내용은 하나만).
  최근 30개·사본 합계 500MB까지(넘으면 오래된 것부터 지움), ⋮로 하나씩·**모두 지우기**로 전부 뺄 수 있다. 앱 백업이 꺼져 있어 사본이 백업으로 나가지 않는다.
  원본이 옮겨졌거나 지워진 줄은 열 때 알리고 목록에서 뺀다.
- 두 손가락으로 확대·축소. PDF·한글은 앱이 쪽 폭을 직접 바꿔 40%~800%를 손을 떼지 않고 한 동작으로 오간다(화면 폭보다 작게 줄여
  여러 쪽을 한눈에 보고, 키우면 옆으로도 스크롤한다. 95~105%에서 손을 떼면 화면 폭에 맞춘다). 분할 화면(폴드 안쪽 화면을 나눠 씀)에서는
  화면을 다 쓸 때의 800% 크기까지 키울 수 있다(창 폭 기준이면 절반 크기에서 멈췄다. 앱이 그 폭을 알려 줌, 최대 2400%).
  확대·축소한 채 화면을 **두 번 톡** 누르면 화면 폭에 맞춘 처음 크기로 돌아간다(PDF·한글은 누른 자리를 그대로 두고, 엑셀·워드·PPT는 웹뷰 배율 1로). 내려 읽는 동안 오른쪽에 쪽 이동 손잡이와
  "지금 쪽/전체 쪽"이 나오고, 손잡이를 끌면 그 위치로 바로 간다(구글 드라이브의 PDF 보기처럼). 위쪽 바에는 파일 이름과 메뉴(⋮)만 있다. 메뉴: **문서에서 찾기**(PDF)·**원본 모양으로 보기**(긴 워드)·
  **문서 안내**·**파일 공유하기…**(받은 파일을 카톡·메일·드라이브 등으로 보냄. 보내기 전에 이름을 고칠 수 있고 확장자는 그대로, 그대로 두면 받은 파일 그대로)·**다운로드**(카톡 등에서 바로 연 임시 파일을
  원본 그대로 휴대폰의 다운로드 폴더에 저장, 같은 이름이 있으면 "이름 (1)")·**인쇄**(안드로이드 인쇄 창에서 프린터를 고른다. PDF가 아닌 문서는
  아래 "PDF로 저장"과 같은 인쇄 모양에 PPT만 둘레 10mm 여백, PDF 문서는 받아 둔 원본 PDF를 그대로 넘긴다(모든 쪽·원래 화질, 쪽 맞춤·고른 쪽은 인쇄 창이).
  작성자가 인쇄를 막은 PDF·열기 비밀번호가 걸린 PDF는 이유만 알린다. 인쇄 창은 지난번에 고른 곳을 기억해 앱이 프린터나 "PDF로 저장"을 미리 고를 수는 없다)·
  **PDF로 저장**(PDF가 아닌 문서. 안드로이드 인쇄 창이 열리고
  프린터 목록에서 "PDF로 저장"을 고른다. 종이는 미리 골라 둔다: 안드로이드 "PDF로 저장"은 정해 둔 종이만 받아(그 밖의 크기는 기본 종이로 바뀜)
  문서 쪽이 흔한 종이(A3·A4·A5·B4·B5·레터·리걸·타블로이드, ±3mm)면 그 종이, 아니면 같은 방향의 A4. 한글은 모든 쪽을 SVG(벡터)로, 워드 쪽 모양은 한 쪽 = 한 장,
  PPT는 슬라이드 한 장 = 가로 A4 한 장(종이에 맞춰 키우고 가운데), 엑셀은 지금 보는 시트를 가로 A4 폭에 맞춰, 워드 읽기 모드·간단 보기는 글 흐름 그대로 A4에.
  글자는 글자로 들어가 PDF에서 찾을 수 있다. 워드·PPT 엔진은 평소 화면 근처만 그리므로 인쇄하는 동안만 모두 그린다)·**연결 앱…**(한컴 뷰어 등 다른 앱으로 열기).
  워드 쪽 모양의 "화면 근처만 그리기"는 표준 CSS zoom(크롬 128부터)을 전제로 쪽 위치를 재서, 그보다 오래된 웹뷰에서는 끝까지 내려도
  뒤쪽 쪽이 그려지지 않았다(에뮬레이터 웹뷰 113). 그런 웹뷰(Element.currentCSSZoom 없음)에서는 모든 쪽을 그린다.
- **일러스트(.ai)**: "PDF 호환 파일 만들기"(일러스트레이터 기본값)로 저장한 파일은 함께 저장된 PDF로 열고, 레이어·아트보드 밖 개체·편집 정보는
  보이지 않을 수 있다고 위쪽 띠로 알린다. 그 옵션을 끄고 저장한 파일(PDF 자리에 안내 글 한 쪽)과 옛 PostScript 형식(일러스트레이터 8 이전·EPS)은
  열지 않고 다시 저장하거나 다른 앱으로 열라고 안내한다. 연결 목록: application/illustrator·vnd.adobe.illustrator·postscript.
- **300MB 한도**: 넘는 파일은 크기를 알려 주는 앱이면 받기 전에 바로, 아니면 받다가 넘는 순간 멈추고 "300MB가 넘는 파일은 열 수 없어요(n MB)"로 알린다.
- **언어**: 휴대폰(앱) 언어가 한국어면 한국어, 그 밖의 언어는 영어로 메뉴·안내·버튼·오류가 나온다(화면은 `assets/viewer/i18n.js`,
  앱 쪽 알림은 `res/values`(영어)·`res/values-ko`). 문서 내용은 그대로.
- **PDF 찾기**: 메뉴(⋮)의 **문서에서 찾기** → 단어 입력 → 찾은 곳이 형광펜으로 칠해지고 ▲▼로 오간다(띄어쓰기·대소문자 차이는 무시).
- **PDF 이미지로 변환**: 메뉴(⋮)의 **이미지로 변환…** → 쪽 그림을 눌러 여러 장 고르거나(지금 보던 쪽이 골라진 채 열림, **전체 선택**),
  "1-3, 5"처럼 범위를 적어 **고르기** → **공유하기**(안드로이드 공유 창 → 카톡 등) 또는 **사진첩에 저장**(사진첩의 "be docs" 앨범).
  해상도는 **400dpi**(기본)와 **600dpi** 중에서 고른다. 글자·선만 있는 쪽은 **PNG**(손실 없음), 사진이 많은 쪽(쪽 안 사진 화소가
  쪽을 150dpi로 본 화소의 25% 이상: 스캔·사진 자료)은 **JPG**(품질 0.95)로 자동으로 만든다.
  PNG는 쪽을 가로 띠(약 800만 화소, 위아래 32행 겹침)로 나눠 그리면서 바로 PNG로 이어 쓴다(행 필터 Up, 압축은 웹뷰 내장 zlib).
  메모리가 띠 하나만큼만 들어 A3 도면 600dpi(9921×7016, 약 7천만 화소)도 만든다(한 장 1억5천만 화소·한 변 16,384px까지).
  통째로 그린 것과 픽셀 단위로 같다(도면 차이 0.003%). JPG는 한 장 2,400만 화소까지(사진 쪽은 원래 사진 해상도 이상은 의미가 없다),
  메모리가 모자라 실패하면 0.7배씩 줄여 다시 그린다. A3 도면 400dpi PNG는 PC에서 약 2초·11MB, 600dpi는 약 4초·16MB.
  카톡은 사진을 "일반화질"이면 줄여서 보낸다(2026-10 확인: A3 300dpi 그림이 2000×1414로 도착). 해상도를 지키려면 카톡에서 "원본"으로 보낸다(창에 안내).
  사진첩에 저장한 그림은 사진 백업(구글 포토 등)에도 올라갈 수 있어 창에 그렇게 알린다. 작성자가 인쇄와 복사를 모두 막아 둔 PDF는 변환하지 않는다.
  안드로이드 10 이상이라 사진첩 저장에 권한을 묻지 않는다. 보내기용 그림은 앱 캐시에 두고 읽기 전용 주소(`ExportProvider`)로 넘기며 다음 내보내기 때 지운다.
  메뉴·문서 안내 목록·찾기 막대·칸 팝업·차트 값 표는 휴대폰의 뒤로 가기로 닫힌다(문서가 닫히지 않음).
- 위쪽 바는 내려 읽는 동안 비켜 주고, 조금 올리면 다시 나타난다(워드·파워포인트도 같다: 바를 접고 그 자리를 문서가 쓴다). 긴 파일 이름은 가운데를 줄이고 끝(버전·확장자)을 남기며, 누르면 전체 이름이 보인다.
- **비밀번호 문서**: 한글·PDF·엑셀(xls 포함)·워드(doc 포함)·파워포인트(2007 이후 형식)는 비밀번호를 물어보고 연다.
- **여는 중**: 5초가 넘으면 안내가 바뀌고(15초·45초에 다시 바뀌며 걸린 시간을 보여줌) **다른 앱으로 열기**가 함께 나온다.
  워드 쪽 나누기처럼 화면이 통째로 멈춘 동안에는 웹 화면의 버튼이 눌리지 않으므로, 앱이 화면 아래에 직접 **다른 앱으로 열기**를 띄운다.
- **긴 워드(약 30쪽 분량 이상)**: 쪽을 나누지 않고 글·표·그림을 위에서 아래로 이어 보여 주는 **읽기 모드**로 바로 연다.
  docx는 워드 엔진을 거치지 않고 문서를 직접 읽어 183쪽 문서도 몇 초 안에 열린다(97–2003 doc는 엔진이 읽은 뒤 연다).
  쪽 나눔·머리말 위치·글꼴은 원본과 다르다(머리말·꼬리말은 맨 위·아래에 한 번, 각주는 끝에 모음). 메뉴나 문서 안내의 **원본 모양으로 보기**를 누르면
  그때 엔진으로 원본 모양을 그린다(문서를 다시 읽고 쪽을 나누는 동안 기다리고, 쪽을 나눌 때 화면이 잠시 멈춘다).
- **엑셀**: 틀 고정한 머리 줄·열은 내리거나 옆으로 밀어도 따라온다. 칸을 누르면 잘린 글자 전체·메모가 뜨고(메모가 있는 칸은 모서리에 빨간 삼각형),
  숨긴 행·열은 엑셀처럼 빼고 그리되 문서 안내의 **숨기기 취소**로 펼친다. 숨긴 시트는 탭 끝의 **숨긴 시트 N개**로 연다. 차트를 누르면 값 표가 나온다.
- **메모·노트**: 문서 화면에 나오지 않는 메모·검토 의견(워드·한글·PPT·PDF·RTF·ODT)과 발표자 노트(PPT·ODP)는
  문서 안내의 **보기**로 목록을 연다. 워드에서 쪽 아래로 넘쳐 잘린 글은 **잘린 글 보기**로, 엑셀 글상자의 잘린 글은 글상자를 눌러 본다.
  그리지 못하는 것(삽입 개체·EMF 그림·수식·워터마크·PDF 첨부 파일 등)은 개수를 알린다.
- 못 여는 파일은 오류 대신 파일 카드와 **다른 앱으로 열기**를 보여준다. 원인은 카드 아래 **자세히**를 누르면 보인다.
  회사 보안(DRM)으로 잠긴 것 같은 파일은 깨진 글자 대신 "보안 프로그램으로 잠긴 문서 같아요"와 보안을 푼 파일을 받는 방법을 안내한다.
  내려받기가 덜 끝나 뒷부분이 없는 파일은 "파일을 끝까지 받지 못했어요"로, 엔진이 끝나지 않는 손상 엑셀은 "파일을 읽다가 멈췄어요"로 안내한다.
  확장자와 내용이 다른 파일(엑셀을 .doc로, 한글을 .xlsx로 보낸 경우)은 내용대로 연다.
  간단히 보여 주거나 일부를 빼고 보여 줄 때는 **문서 안내**로 알린다: 안내를 문서 위에 띠로 쌓지 않고 위쪽 바 아래 한 줄
  (가장 중요한 안내 + "외 N개")로 접어 두고, 누르면 전체 목록이 아래에서 올라온다(각 안내의 **다른 앱으로 열기**·**보기** 등 버튼 포함).
  잘라 보여 준 것(엑셀 3,000행 등)·읽기 모드 안내가 한 줄 요약에 먼저 나오고, 엑셀은 잘린 표 끝에도 짧게 적는다.
  위쪽 한 줄은 보이는 내용에 영향이 있을 때(잘림·그리지 못함·다른 방식으로 엶·앱이 계산한 수식)만 뜬다. 메모·발표자 노트·첨부 파일·
  숨긴 행 같은 참고 안내는 메뉴(⋮)의 **문서 안내**에서만 보인다. AutoCAD 도면 PDF의 검색용 글자 주석(작성자 "AutoCAD SHX Text",
  도면에 이미 그려진 글자의 복사본)은 메모로 세지 않는다.
- **폴드**: 접고 펴도 보던 문서가 유지되고, 펼치면 화면 폭에 맞춰 크게 보인다.

- **화면**: 위쪽 바·메뉴·문서 안내 목록은 반투명 유리(뒤가 흐리게 비침)로 문서 위에 떠 있고, 버튼은 알약 모양이다.
  앱 글자(파일 이름·메뉴·안내·버튼)는 Pretendard 글꼴을 앱 안에 넣어 쓴다(인터넷 없이, 기종과 상관없이 같은 모양, APK 약 2MB 늘어남).
  문서 내용(엑셀 칸·워드·PPT·간단 보기)은 원래처럼 휴대폰 기본 글꼴로 그린다. 색은 앱 아이콘의 남색(밝은 화면)·청록(어두운 화면)을 따른다.

## 한계

이번에 없앤 한계: 비밀번호 걸린 xlsx·xls·docx·doc·pptx, PDF 찾기, 옛 xls 속 그림, 엑셀 칸 배경색, 큰 엑셀에서 화면이 굳던 것, 손상 엑셀·ODT·시트 전체 수식에서 화면이 멈추던 것,
보안(DRM) 파일이 엑셀에서 깨진 글자 표로 보이던 것, 워드 내용 컨트롤(입력 칸) 글자 빠짐, 목차·서식의 탭 채움 점선,
파워포인트 기본 표 스타일, RTF·ODT·ODP·Word 2003 XML·웹 페이지 .doc·Word 2~95(간단 보기).
남은 한계는 아래와 같다. 이런 경우에도 오류 화면 대신 파일 카드·문서 안내로 보여주고, 빠지거나 단순해진 내용은 숨기지 않고 알린다.

- HWP 표시는 오픈소스 엔진 [rhwp](https://github.com/edwardkim/rhwp) 0.8.7(1.0 이전)을 쓴다.
  복잡한 공문서는 줄바꿈·배치가 원본과 다를 수 있다(rhwp 측정: 한컴 2022와 쪽수가 다른 문서 약 4.6%). 한컴 전용 글꼴 대신 휴대폰 글꼴로 표시한다.
- 엑셀 엔진(SheetJS 무료판)은 글자 모양·테두리·틀 고정·차트를 읽지 않아, 앱이 파일을 직접 읽어 채운다(`sheet-format.js`: xlsx의 XML,
  xls의 BIFF 기록 / `sheet-chart.js`: 차트 / `sheet-cond.js`: 조건부 서식). 열 너비는 ECMA-376 공식으로 픽셀로 바꾸고, 기준이 되는 숫자 폭은
  통합 문서 기본 글꼴로 정한다(Calibri 11 → 7px, 맑은 고딕·돋움 11 → 8px: 한국어판 기본 열 8.38 = 72px). 휴대폰 글꼴은 Calibri보다 숫자가 넓어
  영문 숫자는 엑셀보다 조금 더 잘릴 수 있다(잘린 칸은 "…" 표시, 누르면 전체). 파일에 적힌 시트 크기(dimension)가 실제보다 작아도 읽힌 칸은 모두 보인다.
  배경을 칠한 칸의 글자는 파일의 글자색을 쓰되 배경과 대비가 모자라면 배경 밝기에 맞춰 흰색·검은색으로 바꾸고(어두운 화면 설정에서도 읽힘),
  흰색 채우기는 기본 배경으로 둔다. 틀 고정은 고정 부분이 화면 높이의 35%·폭의 50%를 넘거나 병합 칸에 걸치면 고정하지 않고 그냥 흘러가게 둔다.
- 엑셀 차트는 xlsx의 막대(가로·세로·누적·100%)·꺾은선·원·도넛·영역·분산형을 파일에 저장된 값(없으면 칸 값)으로 직접 그린다(보조 축·데이터 레이블·범례 포함).
  3D·방사형·주식형·새 차트(폭포·트리맵 등)·옛 xls의 차트, SmartArt, EMF·WMF 그림, 버튼·확인란은 그리지 않고
  "차트 2개는 표시되지 않아요"처럼 개수를 알린 뒤 **다른 앱으로 열기**로 넘긴다. 도형은 사각형·둥근 사각형·타원·선과 그 안의 글자를 그리고,
  화살표·말풍선 같은 다른 모양은 사각형으로 단순화한다. 스파크라인은 나오지 않는다.
- 엑셀 조건부 서식은 엑셀처럼 우선순위대로 적용하고 겹치지 않는 서식(채우기 + 굵게)은 함께 입힌다(LibreOffice는 첫 규칙만 적용해 일부 다르게 보인다).
  수식 규칙은 앱의 수식 계산기로 칸마다 계산한다. 엑셀 2010 이후 확장에만 있는 규칙(사용자 아이콘·다른 시트 참조 등), 표준편차 기준 평균,
  옛 xls의 조건부 서식은 그리지 않고 "조건부 서식 N개는 표시되지 않아요"로 알린다. 데이터 막대는 단색 반투명으로, 아이콘은 기호 글자로 그린다.
  시트당 처음 3,000행·200열까지 보여주고 그렇게 알린다.
  날짜는 한국어 엑셀처럼 보여준다(기본 날짜 2026-10-07, 요일 aaa·aaaa, 오전/오후, [DBNum1~4] 한글·한자 숫자 — 마지막은 LibreOffice 표기 기준).
  엑셀 해석은 크기와 상관없이 화면과 다른 스레드에서 하고(파일을 받는 동안 미리 띄워 둠), 표는 내리는 만큼 이어 그린다. 10만 칸 파일을 PC 크롬 CPU 4배 느리게
  (중급 휴대폰 근사)에서 열면 첫 화면 약 2.5초, 가장 긴 멈춤 약 0.7초, 내리며 이어 그릴 때 0.3초 이하였다(전에는 6초 굳음).
  압축 데이터가 조금 깨진 xlsx에서 엑셀 엔진(SheetJS)의 압축 풀기가 끝나지 않아 화면이 영구히 멈추던 것을 막으려고, 해석 전에 압축 데이터를
  fflate로 끝까지 풀어 본다. 깨진 곳이 있으면 해석이 20초(1MB마다 8초 더) 안에 끝나지 않을 때 그 스레드를 끊고 "파일을 읽다가 멈췄어요"로 안내하고,
  멀쩡하면(엔진이 끝나지 않을 원인이 없으면) 그 4.5배(작은 파일 90초, 최대 5분)까지 기다린다(엔진을 불러오는 시간은 빼고 잰다).
  처음에는 모든 파일에 20초를 적용했다가, 정상 xlsb 하나(엔진이 시트 이름을 수백만 자로 잘못 읽어 PC에서도 2초)가 CI 에뮬레이터 세 대에서
  모두 20초를 넘겨 "멈췄어요"로 끝나는 오탐을 냈다. 렌더러 프로세스 전체를 12배 느리게 해 같은 오탐을 재현했고, 지금 판은 같은 조건에서 30초 만에 연다.
  열 전체를 합친 병합(A1:A1048576 등)은 그릴 범위 안으로 잘라 펼친다(PC 크롬 6배 감속에서 4~74초 멈춤 → 0.4초).
- 웹 시스템·프로그램이 만든 엑셀 중 수식 결과가 저장되지 않은 파일은 앱이 직접 계산해 보여주고 그렇게 알린다
  (fast-formula-parser + formulajs, LibreOffice 계산값과 63개 수식 비교에서 62개 일치·1개는 LibreOffice가 XLOOKUP 미지원).
  계산도 화면과 다른 스레드에서 10초까지 하고, 같은 범위는 한 번만 읽는다(VLOOKUP·SUMIF 6,000칸: 화면 8초 멈춤 → 멈춤 없이 2초, LibreOffice 값과 모두 일치).
  한 범위가 50만 칸을 넘는 수식(SUM(A:XFD) 등)과 그 칸에 기대는 수식은 값을 지어내지 않고 수식 그대로 둔다(전에는 화면이 영구히 멈췄다).
  계산하지 못한 수식은 수식 그대로 보인다.
- 파워포인트는 [react-pptx](https://github.com/extend-hq/react-pptx) 0.2.2(초기 버전)를 쓴다. pptx의 숨긴 슬라이드도 함께 보여 주며 그렇게 알리고,
  삽입 개체(엑셀 표 등)는 개수를 알린다. 예전 ppt의 발표자 노트·메모는 꺼내지 못한다. SmartArt는 도형만 나오고 글자가 빠질 수 있고,
  예전 ppt(97–2003)는 정렬·글머리·글자 색 같은 서식이 단순해지며(화면 위에 알림) 배경 그림·그라데이션은 흰색으로 나올 수 있다.
  글머리 기호가 문자 참조(`&#x2022;`)로 적힌 파일은 엔진이 풀지 않아 화면에서 기호로 바꿔 준다.
  애니메이션·전환 효과는 없다. PowerPoint 95는 "다른 앱으로 열기"로 안내한다.
- 워드는 [react-docx](https://github.com/extend-hq/react-docx) 0.10.0(1.0 이전)을 쓴다. 쪽 나눔·번호 매기기·머리말·꼬리말·표·그림·내용 컨트롤은 나오지만,
  여러 쪽에 걸친 큰 표 칸은 아래가 잘려 보일 수 있다(본 쪽에서 잘린 글을 찾으면 몇 쪽인지 알리고 **잘린 글 보기**로 보여 준다. 아직 넘겨 보지 않은 쪽은
  넘겨 볼 때 확인한다. 엔진이 같은 글을 다음 쪽에 다시 그린 경우는 잘린 것으로 세지 않는다. 공개 워드 시험 파일 303종에서 4종이 걸렸고,
  4종 모두 원본의 글이 화면에서 실제로 빠진 경우였다). 수식(OMML)·삽입 개체(엑셀 표 등)·EMF·WMF 그림·끼워 넣은 문서·워터마크는 그리지 못해 개수를 알리고,
  변경 내용 추적(수정 표시)은 수정을 받아들인 모습으로 보여 주며 그렇게 알린다. 0.10.0은 0.9.2보다 내용 컨트롤 글자가 빠지지 않는 대신 긴 문서 쪽 나눔이 느려서,
  빌드할 때 느린 부분 두 곳을 고쳐 넣는다(`viewer-libs/patch-react-docx.mjs`, 탭 채움 점선 고침 포함). 뷰어가 멈추면 간단한 보기로 바꾸고 알린다.
- 워드는 쪽을 나누는 동안 화면 스크립트가 멈춘다(엔진이 문서 전체의 문단·표 높이를 첫 화면 전에 한 번에 계산한다).
  그래서 분량이 약 30쪽 이상이면(글자 1,300자·문단 80개·표 줄 40개를 한 쪽으로 어림, 워드 문서 297종으로 맞춤) 읽기 모드로 먼저 연다.
  엔진(react-docx의 wasm)은 쪽을 나누기 전에 문서 구조를 만드는 데도 XML 1MB당 약 2.6초(PC)가 걸려서(48쪽 4.4초, 183쪽 33초),
  docx는 엔진 대신 `docx-read.js`가 작업 스레드에서 문서 XML을 한 번 훑어 읽기 모드를 만든다(183쪽 PC 0.4초). 본문 XML이 120KB 미만인
  짧은 문서는 이 단계 없이 엔진으로 연다.
  렌더러 프로세스 전체(작업 스레드 포함)를 4배 느리게 한 PC 크롬(중급 휴대폰 근사, 실제 기기 시간은 다를 수 있다)에서 첫 화면까지
  걸린 시간(가장 긴 멈춤)은 처음 판 → 엔진 읽기 모드 → 지금 판으로:
  48쪽 docx 26.3초(6.6초) → 20.2초(0.3초) → **1.3초**(0.2초), 20쪽 그림 docx 14.0초(8.9초) → 5.8초(0.4초) → **0.8초**(0.2초),
  36쪽 시험 docx 9.0초(4.0초) → 5.5초(0.4초) → **0.9초**(0.2초), 183쪽 docx는 90초 한도에 걸려 "다른 앱에서 열어 보세요" → 148초 → **5.4–5.6초**(0.6–0.7초, 두 번 잼).
  97–2003 doc는 엔진이 읽어야 해서 31쪽 8.1초(0.4초), 124쪽 22.1초(0.4초)다(처음 판 12.0초·33.1초, 멈춤 4.6초·11.9초).
  읽기 모드에서 **원본 모양으로 보기**를 누르면 그때 엔진이 문서를 읽고 쪽을 나눈다(CPU 4배 감속 쪽 나누기 멈춤: 31쪽 5.2초, 48쪽 7.2초,
  124쪽 11.1초, 183쪽 33초). 5초가 넘으면 앱이 화면 아래에 "다른 앱으로 열기"를 띄운다. 30쪽 분량 미만은 지금처럼 원본 모양으로 바로 열며,
  10쪽 문서도 2.7초쯤 멈춘다(CPU 4배 감속).
  (이전에 적은 워드 시간은 화면 스레드만 느리게 해(CDP) 작업 스레드 시간을 덜 쟀고, 그 전의 48쪽 17초·124쪽 28초는 시험 브라우저의
  자동화 표시 때문에 엔진이 모든 쪽을 그린 값이었다. 지금은 자동화 표시를 끄고, 전체 시간은 프로세스 단위로 느리게 해서 잰다.)
- 읽기 모드는 글·표·그림을 위에서 아래로 이어 그린다. 번호 매기기·제목·정렬·글자 굵기·기울임·밑줄·색·크기(스타일 상속 포함), 표의 합친 칸,
  표 속 표, 그림(PNG·JPEG·GIF·BMP·WebP), 각주·미주(끝에 모음), 머리말·꼬리말(맨 위·아래에 한 번), 확인란, 필드 결과가 나온다.
  docx 빠른 읽기는 글상자 글도 보여 주고, Word처럼 숨긴 글은 빼고 수정 표시는 받아들인 모습으로 보여 준다. 도형·차트·EMF 등 다른 형식 그림·
  쪽 배치·탭 위치·들여쓰기는 빠지고(빠진 그림 수를 알림), 원본 모양에서 보인다. 공개 시험 docx 128종에서 엔진이 읽은 구조로 만든 읽기 모드와
  글을 대조해 116종이 같았고(공백·쪽 나눔 표시 무시), 엔진 글자 538,308자 중 빠른 읽기에 없는 것은 Word에서도 보이지 않는 60자였다(`tools/audit/docx-read/`).
  1,000줄 가까운 표는 100줄쯤씩 나눠 그리고 뒷조각을 첫 조각과 같은 칸 너비로 맞춘다(세로로 합친 칸이 걸친 줄에서는 끊지 않는다).
  첫 화면 분량만 바로 그리고 나머지는 조금씩 이어 붙여, 183쪽 문서도 읽기 모드를 그리는 동안 크게 멈추지 않는다.
- 97–2003 파워포인트(ppt)의 비밀번호 문서, XOR 방식(아주 옛 Word·Excel 95 시절)·인증서로 잠근 문서는 "다른 앱으로 열기"로 안내한다
  (97–2003 엑셀(xls)·워드(doc)의 RC4 비밀번호 문서는 연다. 풀기 결과는 msoffcrypto-tool과 바이트 단위로 같음을 확인했다).
- 회사 보안(DRM) 문서는 그 회사 보안 앱이 있어야 열린다. 업체별 파일 형식은 공개돼 있지 않아 업체를 가리지 않고,
  문서 확장자인데 알려진 문서 구조(ZIP·OLE 본문·PDF·한글 서명)가 없고 내용이 무작위에 가까운 파일, 또는 문서 본문 없이 다른 내용을 감싼 OLE를
  "보안 프로그램으로 잠긴 문서 같아요"로 안내한다(전에는 엑셀 엔진이 이런 파일을 깨진 글자 표 수백 줄로 보여 줬다).
  공개 시험 파일 599종(정상·손상·퍼징 파일)에서 정상 파일을 잠긴 파일로 잘못 본 경우는 없었다. 실제 DRM 파일로는 확인하지 못했다.
- 간단 보기(RTF·ODT·ODP·Word 2003 XML·웹 페이지 .doc·Word 2~95)는 글자·표·그림 위주라 글꼴·배치·쪽 나눔은 원본과 다르다.
  RTF·ODT의 머리말·꼬리말은 본문 위·아래에 한 번, 각주는 끝에 모아 보여 준다. Word 2~95는 글자만 보여주며, 글자 코드는 문서 언어 표시와
  내용으로 고른다(한국어·러시아어 등). 웹 페이지 .doc는 스크립트·외부 연결을 모두 걷어내고 보여주며, 파일 밖에 있던 그림은 개수를 알린다.
- 손상·덜 받아진 파일: 97–2003 문서(OLE)는 할당표가 쓰는 마지막 칸이 파일 밖에 있으면, ZIP 문서는 끝의 중앙 목록 표시가 없으면
  "파일을 끝까지 받지 못했어요"로 안내한다(전에는 잘린 97–2003 문서를 "보안 프로그램으로 잠긴 문서"로 잘못 안내했다).
  앞에 바이트가 덧붙어 온 97–2003 문서는 잘라 내고 연다. 화면 쪽 ZIP 풀기는 [fflate](https://github.com/101arrowz/fflate)로 해서 깨진 압축 데이터에서도
  바로 끝나고(1바이트 깨진 ODT: 28초 멈춤 → 0.2초 안내), 중앙 목록이 깨진 ZIP은 항목 머리글을 직접 훑어 찾는다.
  엑셀 구조(OLE·ZIP·BIFF)가 없는 이진 파일은 깨진 글자 표 대신 "엑셀 파일로 읽을 수 없어요"로 안내한다.
  ZIP 끝에 적힌 항목 수가 틀린 xlsx는 고쳐서 읽고(엔진이 20초 넘게 헤매던 것 → 0.5초), 시트 내용이 XML이 아닌 손상 시트는
  "빈 시트"라고 하지 않고 "이 시트는 손상돼 내용을 읽지 못했어요"로 알린다(모든 시트가 그러면 파일 전체를 손상으로 안내).
  엔진이 칸·문단마다 경고를 내는 파일이 있어 콘솔 메시지는 문서마다 화면 쪽 300개·기기 기록 200줄(줄마다 300자)까지만 남긴다.
- 한셀·한쇼(.cell·.show)는 "다른 앱으로 열기"로 안내한다. 문서가 아닌 일반 압축 파일(ZIP)은 "압축 파일이에요"와 푸는 방법을 안내한다.
- HWP는 쪽을 그림으로 그려서 글자를 길게 눌러 고르거나 복사·찾기를 할 수 없다(PDF·워드·PPT는 된다).
  한글 메모는 엔진이 그리지 않아 앱이 본문 기록(HWP 5.0)·XML(HWPX)에서 직접 꺼내 **보기**로 보여 준다(비밀번호·배포용 문서는 제외).
- 쪽수가 아주 많은 HWP(수천 쪽)는 여는 데 오래 걸린다(1만6천 쪽 기준 PC에서 약 2분). 그동안 화면은 멈추지 않고 "다른 앱으로 열기"를 함께 보여준다.
- PDF는 [pdf.js](https://github.com/mozilla/pdf.js)(Firefox의 PDF 엔진)로 그린다. 글자를 길게 눌러 고르고 복사·찾기를 할 수 있고,
  문서 속 웹·메일 링크를 누르면 브라우저·메일 앱으로 넘어간다(앱 안에서 웹을 열지 않는다). 서식 칸은 보기만 되고 입력은 안 된다.
  메모 주석(검토 의견)은 **보기**로, 첨부 파일은 이름과 개수를 알린다(첨부 파일을 앱 안에서 열지는 않는다, 앞 300쪽까지 확인).
  pdf.js가 열지 못하는 파일은 안드로이드 내장 렌더러로 다시 시도한다(이때는 주석·글자 선택·찾기가 빠지며 그렇게 알린다). 스캔한 PDF는 글자가 없어 찾기가 안 되고 그렇게 알린다.
  찾기 형광펜은 글자 조각(보통 단어나 줄) 단위로 칠한다.
  쪽은 화면 해상도로 그리고, 두 손가락으로 확대한 뒤 손을 떼면 보이는 부분만 그 배율의 해상도로 다시 그려 겹친다(아크로뱃처럼 글자가 흐리지 않게).
  화면 위아래 2장 거리 안의 쪽을 미리 그리고, 3장 밖으로 멀어지면 메모리를 위해 비운다. 비울 때는 그 쪽의 작은 그림(가로 640px JPG,
  한 장 수십 KB, 최대 400장)을 대신 두어 되돌아오면 바로 보이고, 선명한 그림을 다 그리면 바꿔 끼운다(사진 많은 PDF에서 끝까지 내렸다
  올리면 다시 "불러오는 중"이 보이던 것). 쪽은 화면 밖 캔버스에 다 그린 뒤 한 번에 붙인다(붙여 둔 캔버스에 조금씩 그리면 웹뷰가 프레임마다
  그 큰 그림을 다시 올려 다른 쪽 그리기가 느려졌다).
  도면(CAD)처럼 선이 수만 개인 PDF에서 최신 크롬은 `Path2D.closePath()`가 경로 길이에 비례해 느려져 쪽 하나에 몇 초씩 화면이 멈췄다
  (닫힌 삼각형 1만6천 개: 크롬 109는 6ms, 141은 약 0.9초 — 직접 잰 값). 빌드할 때 pdf.js의 경로 만들기를 SVG 경로 글자로 한 번에 만들게 고쳐 넣는다
  (`viewer-libs/patch-pdfjs.mjs`. 시험 PDF 30종을 고치기 전과 픽셀 단위로 비교해 차이 0).
- 휴대폰의 "Android System WebView"가 아주 오래된 경우(Chrome 98 이전 수준) 문서를 열지 않고 업데이트 방법을 안내한다.
  그보다 새 웹뷰는 업데이트하지 않아도 된다: pdf.js가 최신 크롬(114~128)에만 있는 기능 다섯 가지를 그대로 써서
  `assets/viewer/pdf-polyfills.js`로 채운다(이게 없으면 안드로이드 14 기본 웹뷰에서 비밀번호 PDF·도장이 빠졌다).
  크롬 103·106·109·113·141 엔진으로 버전별 123종 전부를 확인했다.
- 휴대폰 글자 크기 설정은 앱 버튼·안내 글자에만 적용하고 문서는 원래 크기로 그린다(문서 배치가 깨지지 않게). 문서는 두 손가락으로 확대한다.

```
                                            react-docx·pdf.js 문제 고침(patch-react-docx.mjs·patch-pdfjs.mjs), 비밀번호 xlsx·docx·pptx·xls·doc 풀기(office-crypto-entry.js),
                                            수식 계산기(formula-entry.js), ZIP 항목 풀기(inflate-entry.js)
scripts/fetch-vendor.sh                     위 라이브러리와 SheetJS를 받아·묶어 assets/viewer/vendor 에 넣는다
```

앱이 뒤에 있는 동안 시스템이 웹 화면을 정리하거나 앱을 끝내도, 돌아오면 받아 둔 사본으로 문서를 다시 연다.
문서 때문에 웹 화면이 죽으면 앱을 닫지 않고 "다른 앱으로 열기" 안내를 보여준다.

웹 뷰어는 가짜 주소 `https://appassets.androidplatform.net/`에서 열리고, 이 주소로 가는 요청은
`ViewerActivity`가 가로채 앱 안의 파일로 응답한다. 다른 주소로 가는 요청은 모두 막는다.

## 직접 빌드

JDK 17, Android SDK, Node.js가 필요하다.

```bash
./scripts/fetch-vendor.sh      # rhwp, react-pptx, react-docx, pdf.js, 수식 계산기, 비밀번호 풀기, ZIP 풀기, SheetJS 받기 (빌드 전에 한 번)
./gradlew assembleRelease      # app/build/outputs/apk/release/app-release.apk
./gradlew connectedDebugAndroidTest   # 연결된 기기·에뮬레이터에서 테스트
```

배포 키 하나로 팀원 APK·갤럭시 스토어 APK·플레이 업로드 번들을 모두 서명한다: `RELEASE_KEYSTORE_FILE`·`RELEASE_KEYSTORE_PASSWORD`·
`RELEASE_KEY_ALIAS`·`RELEASE_KEY_PASSWORD` 환경 변수를 주고 `./gradlew assembleRelease bundleRelease`
(→ `app/build/outputs/apk/release/app-release.apk`, `app/build/outputs/bundle/release/app-release.aab`).
환경 변수가 없으면 저장소의 디버그 키 `app/debug.keystore`로 서명한다(스토어에는 못 올림).
CI는 GitHub 비밀값 `RELEASE_*`가 있으면 그 키로 서명한 APK·번들을 Artifacts `be-docs-apk`·`be-docs-aab`로 남기고,
없으면 디버그 키 APK만 남긴다. 배포 키는 저장소에 넣지 않는다.
